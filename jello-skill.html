A Claude skill for smart contract review

What it solves

Most AI review tools jump straight to flagging issues. That floods you with false positives and quietly narrows your thinking to whatever the tool already flagged, instead of the full range of attack vectors the codebase has.

Jello builds understanding first. You form your own mental model of the protocol and write your own attack scenarios, so review time goes into judgment, not orientation.

The four passes

Each pass runs on its own. Say its trigger and you get that pass only.

  • Docs deep divedocs passPer-contract roles, protocol summary, user flows, known issues from the docs, and consolidated invariants.
  • Periphery and Uniswap crawlperiphery checkWhat router, hook and pool-manager surfaces call, expect back and fire on.
  • Integrator crawlintegrator checkHow external contracts connect to the base contract: entry points, approvals and callbacks.
  • Math passmath passThree-phase extraction, dedupe, then one consolidated model of invariants, encoding and constraints.
  • Full runcurious jello or run jelloAll four passes, in order.

Modes

Choose how much Jello relies on your docs.

strict

Checks invariants against the docs you supply, and asks for them if they are missing.

relaxed

Infers everything from the code alone.

Modes apply to the docs deep dive and full runs. The math pass and the crawls read docs when they are available, without asking.

Rage mode

jello rage is a separate, opt-in trigger that flips the default. Instead of building understanding, it runs an attacker-mindset pattern match against a 14-category audit checklist. The categories include access control, reentrancy, oracle manipulation, math, DoS, governance and front-running, plus ERC-3643, ERC-4626, ERC-7518 and Uniswap V4 hooks.

Every lead is proof-gated. It is reported only after the exact code path, function and trigger condition are traced and confirmed. An unproven suspicion gets one summary line, and anything less is left out.

Use it as a starting point, never a substitute for your own review. This is the one place the "no findings" rule is suspended, and the exception never carries into a normal run.

Knowing which run you got

Every response opens with SCOPE: and MODE: lines, so you can see which pass ran and how. Automatic matching also works when your request clearly describes the task.
